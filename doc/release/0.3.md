# CAN Networks

- The API no longer connects to a CAN network implicitly. On startup it only searches for networks. Set the environment variable `ICOAPI_CAN_AUTOCONNECT=1` to connect once on startup (headless operation), or use `PUT /can/connect`.
- Add endpoints `GET /can/networks`, `PUT /can/connect` and `PUT /can/disconnect`
- Routes that need the CAN connection now return `503` if no network is connected
- `PUT /reset-can` disconnects, searches for networks again and reconnects if the API was connected before (or autoconnect is enabled)

## Breaking Changes

- The state field `can_ready` (HTTP, WebSocket, MQTT) was renamed to `can_network_found`. It is `true` if at least one CAN network was found, no matter if the API is connected to it.
- New state fields: `stu_connected`, `can_status`, `can_networks`, `can_selected` and `can_error`
